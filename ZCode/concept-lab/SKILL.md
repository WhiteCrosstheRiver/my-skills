# Concept Lab — 一个 HTML 讲明白

来源:Andrej Karpathy(2026-10-02,X)四层讲解法(受控英语 → 图 → 交互网页 → 视频)。
本 skill 取其前三层,收敛成**唯一交付物:一个 self-contained HTML**。不做视频。
视频层资料保留在 references/video.md,默认停用,用户明确点名才启用。

**核心纪律:内容只写一次。** 第 1 层的受控英语稿是唯一的事实来源。
后面每一层都从这份稿子派生。派生层不许引入稿子里没有的公式、数值或结论。
形式越好看,错误越容易让人信以为真。所以正确性全部前置到第 1 层把关。

## 流水线

```
摸底 → ① 受控英语稿 → ② 示意图 → ③ 交互讲解 HTML(唯一交付物)
```

### 0. 摸底(一段话内完成,不单独开轮次)

从对话上下文推断用户水平。推断不出,就在最终回复开头用一句话确认。
明确三件事:讲给谁、讲到什么深度、有无具体困惑点。
一个概念一个页面。用户问"位错和相变",就做两页。不要塞进一个 HTML。

### 1. 受控英语稿(唯一内容层,先写对再谈形式)

**直接执行 ste-speech skill 的全部规则**(若该 skill 可用)。它就是本层的写作规范。
STE 规则之外,本层另加三条硬要求:

- 每个术语首次出现给英文原词。之后只用一个固定叫法。
- 公式在此层定型。自查三件事:量纲一致、极限行为合理(如 r→∞、T→0)、数值与教科书对得上。自查结果写进稿子的"自检"小节。
- 稿子结构固定:`这是什么(一句话)→ 为什么需要它(没有它会怎样)→ 怎么工作(3–6 步)→ 常见误区(2–3 条)→ 自检`。

### 2. 示意图(从稿子派生)

- 每图只讲**一个**结构或过程。结构用 SVG,流程用 Mermaid。
- 图上标注的每个名词必须来自稿子。
- 发现画不出来的段落,通常是稿子那段没想清楚。回去改稿,不要硬画。

### 3. 交互讲解 HTML(默认交付物)

单文件 self-contained HTML。全部内联。无 CDN 依赖。断网可开。

- **风格 = book-distiller 阅读页同源**(纸面美学、oklch 配色、衬线正文)。
  不要从零设计。**从 `assets/template.html` 开始改**,它已含全部 CSS、页面骨架和画布脚手架。
- 设计规格与必备交互清单见 **references/html-spec.md**。动手前必读。
- 必含:每个控件旁一句"你在看什么"、常见误区卡、3 道带解析的自测题、暂停/重置按钮。
- 数值控件读值后必须 clamp。除法先判零。页面不可见时动画自动暂停。
- 默认写到桌面:`Desktop/<概念名> - 讲解.html`。
- 完成后渲染 PNG 交 visual-judge 验收。模拟类页面另测一次极端参数不出错。

### 4. 视频(默认停用)

不做。用户明确点名"要视频"才启用,届时读 **references/video.md**(3B1B 原则 + ManimCE 骨架)。
没有点名,就把全部精力花在把那个 HTML 做好。

## 质量门(交付前过一遍)

- [ ] 稿子里的每个数值/公式在 HTML 里原样出现。派生层没有私自新增
- [ ] HTML 断网可开,无外部请求
- [ ] 所有滑块拖到极值,页面不崩。数字变 NaN/Infinity = 不合格
- [ ] 一句话能回答:用户关掉页面后应该记住什么?答不出,就砍内容
