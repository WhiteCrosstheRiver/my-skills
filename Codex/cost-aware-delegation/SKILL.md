# 成本敏感的子智能体委派

主对话保留用户选择的模型和推理深度。本 skill 只约束**子智能体**的选择；不能在运行中的主对话里假装切换模型。先判断是否需要委派：只有存在边界清楚、可独立验收的子任务，且委派能减少主对话工作或缩短关键路径时才创建子智能体。简短任务直接完成，避免代理启动、传递上下文和重复审查的开销。遵守当前会话的代理数量限制；会话或用户禁止委派时不启动代理。

## 选择规则

先定义交付物和验收标准，再按**失败代价、歧义、跨文件/跨工具依赖、可并行性**选择最低足够档位。下表是起点，不是价格或质量保证。这里的 Light 对应工具参数 `low`，Extra High 对应 `xhigh`。

| 子任务特征 | 首选模型 | 推理深度 | 例子 |
| --- | --- | --- | --- |
| 输入和输出明确，步骤少，容易机械核对 | `gpt-6-luna` | `low` | 查找文件、提取事实、局部格式修改、执行明确命令 |
| 需要少量判断，范围局部，验收清晰 | `gpt-6-luna` | `medium` | 小范围代码修改、整理多个来源、补充局部文档 |
| 多步分析或实现，但边界清楚且可测试 | `gpt-6-luna` | `high` | 有明确接口的功能、定位可复现故障、结构化研究 |
| Luna 高深度仍难稳定完成；存在复杂权衡、广泛改动或较高返工成本 | `gpt-6-sol` | `medium` | 跨模块设计、复杂重构、综合方案初稿 |
| 需要持续架构判断、复杂 UI 设计或可执行的完整 plan，且 Luna/Sol Medium 不足以覆盖风险 | `gpt-6-sol` | `high` | 多页面体验设计、系统迁移计划、难复现问题 |
| 最难的端到端工作，跨代码、应用、研究和多轮工具判断；错误代价高 | `gpt-6-astra` | `medium`，必要时 `high` | 高歧义产品设计、复杂系统诊断、关键方案审查 |

不要只因任务名字叫“UI”或“plan”就自动选高档；看实际范围、现有规范、可验收性和失败代价。`luna xhigh/max`、`sol low/xhigh/max`、`astra low/xhigh/max` 不是默认升级阶梯：只有明确理由说明它比相邻模型档位更合适，且该档位在当前客户端可用时才用。不要使用 Ultra 作为省钱手段；Ultra 会引入额外代理。速度模式 Fast/Ultrafast 与推理深度分开判断，不因需要更深推理而开启。

## 委派与升级

1. 给子智能体一个最小而完整的任务说明：目标、相关文件或来源、约束、验收标准、允许的副作用、报告格式。仅传必要上下文。没有足够独立的工作时保持单代理。
2. 创建子智能体时显式指定 `model` 和 `reasoning_effort`；若工具要求，使用有限历史或无历史 fork，避免默认继承主对话的 Sol 档位。若当前工具不能指定模型或档位，不声称已经按此表路由；由主对话完成或说明限制。
3. 子智能体交付后由主对话验收：检查关键事实、diff/文件、测试或渲染结果，并与原目标核对。子智能体的“已完成”不是验收通过。
4. 失败先区分原因。缺少输入、工具故障、测试环境问题，先补信息或修环境；局部错误可在原档位定向修一次。若失败来自能力不足、反复漏约束或复杂权衡，再升一级并传递失败证据。避免多个模型重做整项任务。
5. 高风险或不可逆动作仍按用户和会话权限处理；委派不扩大授权。由主对话整合最终结果，说明验收证据和未解决风险。

## 成本口径

优化的是**完成且验收通过的整项任务用量**，包含主对话协调、子智能体执行、重试和审查。不要用单次调用价格替代总成本。2026-09-30 的 [Artificial Analysis 同口径基准](https://artificialanalysis.ai/methodology/intelligence-benchmarking)提示：模型与推理档位之间会出现成本交叉；这只是公开基准的平均任务估算，不能换算为 Codex Pro 实际额度。不要在路由时依赖固定美元表或把能力指数当成成功率。模型可用性、档位和计费规则变化时，以当前工具能力和[官方 Codex 模型文档](https://learn.chatgpt.com/docs/models)为准。若用户明确指定模型、推理深度、成本上限或禁止委派，其要求优先。
