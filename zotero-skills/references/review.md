# 证据驱动的版本化综述

## 准备

`zotero-skill review --title "领域综述" --source-run PATH`（可多次指定 source-run），或用 `--collection KEY` / `--topic "短语"` 读取本机已发布的笔记。只纳入已发布并通过校验的笔记。输出里的 `tiers` 显示有多少 deep / brief / stub 笔记；`matrix.json` 每行带 `tier`、`takeaway`、`question`、`method`、`results`、`conflicts`。

## 三层证据，三种写法

准备命令同时生成 `review-scope.json`（原始检索批次、未筛/暂缓、尚无已发布笔记的文献）、`evidence-cards.json`（完整 claims 与定位）、`synthesis-workbook.md`（问题、证据、可比性与分歧底稿）。先检查范围；工作底稿不是完成的综述。发布产物会自动显示范围说明，不能把 583 候选 → 19 入选 → 3 deep 表述为完成全领域综述。多个 source-run 的候选可能重叠，不把批次数量简单相加。只有收藏夹或 distill 输入时，原始检索覆盖率未知；尽量同时传入来源 deep-search run。

一篇综述的质感主要取决于：精读过的论文讲透，没精读的论文放在合适的位置，不装作读过。

| 笔记深度 | 在综述中的角色 | 写法 |
|---|---|---|
| deep | **锚点**：承载机制、数字与比较 | “作者在 X 条件下测得 Y（单位）[R3]”；可以进比较表 |
| brief | **簇成员**：说明方向、路线和待核证据 | 按问题综合，重要独特工作仍应点名。关于多篇的计数和“均报告”等概括须有覆盖所有成员的 claim refs。已有全文但简报化的核心文章先升级精读；不能仅凭层级标签声称已核验或未取得全文。 |
| stub | **待读清单** | 只进附录表（题名、年份、所属簇、为什么值得读），**不进正文叙事** |

禁止的写法：

- 逐篇串讲（“A 做了…；B 做了…；C 做了…”）。这是目录，不是综述。
- 为了“覆盖全部文献”而写出“标题显示该工作涉及…”一类句子。标题级信息只属于附录。
- 把 brief 论文的数字和 deep 论文的数字放进同一张比较表。
- 精读子集冒充全量覆盖。开头的范围说明写清：检索到多少、精读多少、简报多少、占位多少，以及锚点是怎样选的。

## 动笔前：三张底稿

先分析，再组织叙事（宿主自建辅助记录即可，不改变命令与文件结构）：

1. **问题—证据地图**：每个核心问题下列出支持结果、适用条件、反向证据、替代解释、未解决问题。
2. **可比性表**：比较之前核对对象、任务、数据划分、指标定义、参考标签、软件版本、硬件、计算预算，标注可直接比较 / 有限可比 / 不可比。不可比的结果可以并列，但不能排名或给出通用倍数；跨研究数值给范围与条件，不做简单平均。
3. **综合判断清单**：每个核心综合结论写明由哪些结果支持、文献之间是复现/互补/外推/分歧中的哪种关系、依赖什么假设、仍然不能推出什么。

然后先写**总纲**并自审：3–5 个核心问题（标注在哪章回答）、一条贯穿的论证主线、章节表（每章标题 + 一句作用）、写作约定（符号、单位、引用格式）。主线可以包含分歧和证据不足；年代先后不等于因果。总纲不过关，不写正文。

问题数量按领域宽度调整，3–5 只是单一主线的起点；大型领域可按分支分卷/分层，但不能省略尚未阅读的分支并宣称完成。每个主要结论都回查：是否只有一篇或同一团队的证据？有无相反结果、外部验证或适用条件差异？需要时返回检索/精读，不靠增加文字弥补证据。

## 写作

- **按问题、机制或争论组织章节**，不按论文组织。每章开头一句说明这一章要回答什么，结尾一句过渡到下一章。
- **一段一个论点**，节奏是：问题 → 直觉 → 证据 → 数字。段与段之间用显式的因果或转折连接。
- **新概念先讲为什么需要它**，再给定义与公式，最后给“谁在什么体系上测到什么数字”。比喻只能辅助，不能替代定义。
- **深入浅出不是简写**：重要机制按“现实问题 → 直觉 → 最小例子 → 正式机制/公式 → 条件化证据 → 失败边界”展开。解释术语之间的联系、指标如何对应研究目标；必要的基础知识放在读者第一次需要它的位置。示意例子明确标注，不当作实验结果。
- **详实来自解释和比较**：说清不同路线为什么作出不同取舍，哪些结果可比，分歧由什么证据支持，下一项什么实验能区分解释。不要用若干 bullet 或一张路线表替代全文论证；不要把定量综述写成方法名、结果和形容词的拼接。
- **数字都有出处**：（第一作者 年份）+ [R#]。没有无出处的数字。
- **四层陈述可辨认**：作者报告 / 作者解释 / 综述推断（标 [推断]）/ 研究建议。“在所测体系中”“可能”等限定词在综合时不能消失；有限测试不能写成普遍成立或“首次”。
- **有趣来自问题本身**：反直觉现象、真实分歧、没人测过的条件。不靠夸大比较、编造因果或英雄叙事。
- **提示框克制使用**：“新手路标”（可跳过的概念解释）、“工程判据”（适用任务、依据、前置条件、验证方式、失败信号；证据不足时给测试方案，不编造阈值）、“口径注”（不同文献的定义差异）每章最多各一个，没有必要就不用。
- **删减**：删掉重复的证据摘要、空泛过渡，以及任何换一个领域仍然成立的句子。

一个好段落（虚构示例）：

> 数据效率是等变模型最常被引用的优势，但证据集中在小分子基准上。在 rMD17 上，三种等变模型用 1000 个构型即达到不变模型用 5 万个构型的力误差 [R2][R5]；而在含溶剂的体系里，唯一的直接比较只发现约 1.5 倍的差距，且训练集构成不同 [R9]。所以“数据效率提高一个数量级”目前只对气相小分子成立 [推断]。

对应的差段落：“等变模型近年来取得了显著进展，多项研究表明其具有更高的数据效率和精度，为分子模拟开辟了新方向。”

## 文件与引用

`review.md`：一级标题 + 若干 `##` 章节，公式用 `$…$` / `$$…$$`，事实段落与比较表标 `[R1]` 等。每章至少有一处证据引用。附录“待读清单”可以是 `##` 章节，引用相应 stub 的 metadata claim。

`review-claims.json`：`{"id":"R1","statement":"可核查的综合结论","kind":"reported|synthesis|limitation","refs":["ITEMKEY:C1"]}`。refs 必须指向纳入笔记中真实存在的 claim；复杂综合应有多篇支持；不同指标或基准之间不排名。

## 审查与发布

初稿后至少独立通读一轮：

- **证据审查**：每条声明是否被指定来源支持；核心结论和高风险数字回到原文页/表/图核对，不只看笔记。
- **综合审查**：比较是否公平、推理是否成立、是否漏掉关键问题、正文是否兑现了总纲的主线；检查概念断层、无出处数字、口径冲突、章节过渡。

存在影响核心结论的数值错配、单位错误、版本混用、证据不支持或未标注的外推时，不得标为审查通过；明确标注的未知与未决问题可以保留。通过后保存 `audit.json`：`status: passed`、`reviewer`、`draft_hash`（review.md 按 UTF-8 读取、统一 LF 后的 SHA256）、`review_hash`（`review.audit_hash(run)`）、`checks` 列表。自动校验只能核对引用存在，不能代替语义审查。

发布：`zotero-skill review --publish --run PATH`。生成 Markdown、离线 HTML（本地 KaTeX）、比较矩阵、证据清单、版本清单与变化记录；在 Zotero 中保存 report 条目、阅读便条、Markdown 与离线 ZIP。正文或输入变化会生成新的时间戳版本，相同任务复用，不覆盖历史。

更新时重新 prepare，沿用相同 title；报告新增/移出的论文、笔记版本变化、综合声明变化与未决争议。离线查看需复制整个版本目录，单独复制 HTML 会缺少字体与证据文件。
