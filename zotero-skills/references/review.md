# 证据驱动的版本化综述

准备：`zotero-skill review --title "领域综述" --source-run PATH`，可多次指定 source-run；也可按 `--collection KEY` 或 `--topic "短语"` 读取本机已发布笔记档案。仅纳入已完成并验证的笔记，不能把等待分析的条目当成精读输入。

先阅读 `matrix.json` 的问题—方法—结果—证据等级—冲突矩阵及 `sources/KEY/` 完整笔记。按实际领域组织长篇章节，避免逐篇摘要拼接：比较可比的对照、区分材料/数据/硬件/版本条件、保存冲突和未解决问题。结果外推必须明确是分析者推断。

**综述证据基数 = 全量库（应得尽得，全量覆盖）**。纳入边界等于检索边界，不等于精读子集：

1. **全量纳入**：检索发现的全部相关文献（扣除真噪声）都在综述的证据基数内；禁止以精读子集冒充全量覆盖，禁止把未精读文献表述为"供后续扩展"而排除在综述之外。
2. **证据分层**：深度锚点（13 栏精读笔记，[R#] 引用层）↔ 摘要级（程序化提取，聚类与计数）↔ 标题级（存在性与分类）。每层显式标注；摘录/元数据缺失导致的分类受限如实声明。
3. **全量程序化分析**：对全量库做可复现的统计（年份/期刊/方法家族/主题聚类的脚本化分析），每个主题类报告全量计数与构成；章节按全量聚类组织，深度锚点在章内提供机制与数值深度。
4. **双层写作**：每章 = 全量层的"这一类有多少、什么构成、趋势如何"+ 锚点层的深读证据；两层引用方式不同（统计数字标注"综述者程序化统计，脚本可复现" vs [R#] 回溯笔记）。
5. 精读子集的选择理由与全量库的关系必须声明（锚点是分层深度的顶端，不是覆盖范围的边界）。

**先声明增值与选文方法学**。动手前回答两个问题：①本综述的 added value 是什么——显式化研究缺口、分析方法优劣、提出概念框架或研究议程之一或组合；「某领域新进展」是主题不是可论证的问题。②文献从哪里来：区分"固定文献集合的专题综述"与"面向当前领域的综述"，分别记录文献覆盖截止日期与报告生成日期，写明纳入/排除标准与前向/后向 snowballing——这些进综述开头的范围说明。固定集合之外的新资料只作待补充来源，不冒充已完成精读的输入。宁深勿泛：先窄后扩，不在浅层铺大摊。

**综合分析先行：先分析证据，再组织叙事**。在总纲之前完成三张底稿（宿主自建辅助记录即可，不改变现有命令与文件结构）：

1. **问题—证据地图**：按核心问题整理已有结果、支持来源、适用条件、反向证据、替代解释与未解决问题。不要求所有论文进入正文，也不以共同作者关系强行连接主题。
2. **比较条件表**：任何比较之前核对对象、任务、数据划分、指标定义、参考标签、软件版本、硬件、参数与计算预算；标注可直接比较、有限可比或不可直接比较并说明原因。不可比结果可并列展示，但不得据此给出总排名或通用倍数；跨研究数值不简单平均，给范围与样本量/条件。
3. **综合判断清单**：每个核心综合结论写明——由哪些结果支持、跨文献之间是什么关系（复现/互补/外推/分歧）、推理依赖哪些假设、哪些结论仍然不能推出。并列介绍多篇论文不自动构成跨文献综合。

写作全程区分四层陈述：**作者报告、作者解释、综述推断、研究建议**在正文中可辨认；「有望」「在所测体系中」「可能」等限定在综合时不得消失；禁止将有限测试扩写为必然成立、全部覆盖或首次实现。

**框架先行，多轮成稿**。综述是长文档，必须先定框架再填内容，允许跨多轮迭代打磨。验收标准四条：信息全面、逻辑清晰且层层推进、具备阅读趣味性、深入浅出。流程：

1. **总纲先行**：动笔正文前先写"总纲"并单独自审——①综述回答的 3-5 个核心问题（标注在哪章解决）；②一条贯穿的"逻辑链"（箭头图把主线索从起点串到结论，每环标注章节）；③章节表（每章标题+一句角色定位）；④写作约定（符号、单位、引用格式、口径规则）。**总纲由问题—证据地图形成**，主线允许包含分歧、证据不足与非唯一解释；年代先后不得自动写成因果关系。总纲不过关不写正文。
2. **章节架构**：按**主题、机制或辩论**组织正文，不按文献逐篇组织（逐篇串讲是概览不是综述）。绪论用直观场景开场并给量级感（具体数字），点明"为什么是现在"；概念密集领域设"概念工具箱"章扫清断层；主线章按"机理→方法→应用→系统/工程→开放问题"因果链层层推进；每章开头一句任务声明、结尾一段到下一章的过渡；收束章列开放问题。
3. **概念不断层**：每个新概念首次出现时，先讲它为什么存在（解决什么痛点）、直观图像（可用比喻），再给公式，最后给"谁在什么体系上量过什么数字"。**比喻只能辅助理解，不能替代公式、定义与机制**；背景知识适度折叠，避免工具箱章与正文大量重复。
4. **双读者路径**：「🌱 新手路标」为可跳过的概念解释；「🛠 工程判据」为可直接使用的数字/规则/选型决策——**每条判据含适用任务、依据、前置条件、验证方式与失败信号；证据不足时提供测试方案，不编造精度阈值或通用规则**；「⚠️ 口径注」标明不同文献的测量或定义口径差异，绝不默默替换数字。
5. **数字全部带出处**：正文每个量化结论以（第一作者 年份）标注；章末列"本章引用文献"并注明每篇用于哪一节。不出现无主数字。
6. **可读性最后优化**：段落间用显式因果/转折衔接；每节保持"提出问题→给直觉→验证→落到数字"节奏；适度设问；一段一个论点；删去重复证据摘要与空泛过渡。**趣味性优先来自问题、反直觉现象、机制与真实分歧，不得通过夸大比较、制造因果或英雄化叙事获得**。
7. **双重审查迭代**：初稿后至少独立通读一轮。**证据审查**逐项判断每条声明是否被指定来源支持；**综合审查**判断比较是否公平、推理是否成立、是否遗漏关键问题、框架是否兑现总纲逻辑链；并检查概念断层、无主数字、口径冲突、章节过渡断裂。核心结论与高风险声明必须回查原始来源（原文页/表/图），不只检查笔记。修完再走下述审查发布流程。不求一次完工，求每轮可交付。
8. **发布阻断**：存在影响核心结论的数值错配、单位错误、版本混用、证据不支持或未标注外推时，不得发布为审查通过；明确标注的未知、排除项和未决问题可以保留。

编写 `review.md`：一级标题及若干 `##` 章节，公式用 `$...$`/`$$...$$`，事实段落与比较表标记 `[R1]` 等。另写 `review-claims.json` 数组：`{"id":"R1","statement":"可核查的综合结论","kind":"reported|synthesis|limitation","refs":["ITEMKEY:C1"]}`。refs 必须指向纳入笔记的真实 claim，复杂综合应有多文献支持。不能跨不同指标或基准直接排名。

请独立审查正文与证据，重点检查数值、单位、方法遗漏和过度解释。审查通过后保存 `audit.json`：`status: passed`、`reviewer`、`draft_hash`（review.md 读取为UTF-8文本、统一LF后的SHA256）、`review_hash`（调用 `review.audit_hash(run)`，绑定正文、声明、来源版本）、`checks` 列表；有阻断项先修稿再复审。自动验证只能核对引用存在，不能代替语义审查。

发布：`zotero-skill review --publish --run PATH`。生成 Markdown、离线 HTML、KaTeX本地资源、比较矩阵、证据清单、版本清单及变化记录；Zotero 中保存 report 条目、阅读便条、Markdown 和完整离线 ZIP。每次正文/输入版本变化生成新时间戳目录；再次发布相同任务复用，不覆盖历史。任务中断可用 resume 继续。

更新时重新准备源笔记，沿用相同 title；报告新增/移出论文、笔记版本变化、综合声明变化与未决争议。版本目录完整复制可离线查看，单独复制 HTML 会缺少字体及证据文件。
